# Content Patterns

Patterns for public-facing marketing and editorial content pages. These patterns compose design system components into standard page sections.

---

## 1. Hero Section

The primary above-the-fold section on a landing page.

### When to use
- Homepage and key landing pages.
- When you need to communicate the product value proposition immediately.

### Anatomy
- **Headline**: 1 clear statement of value (max 10 words). Use `<h1>`.
- **Supporting copy**: 1–2 sentences expanding on the headline. Use `<p>`.
- **Primary CTA**: single Button (default variant). Use `<a>` or `<button>`.
- **Secondary CTA** (optional): link or ghost button.
- **Media**: illustration, screenshot, or video (optional; right side or below copy).

### Do
- One primary CTA per hero.
- Keep the headline under 10 words.
- Ensure the hero works without the media (always test with images disabled).

### Don't
- Do not use a hero section inside a dashboard or application UI.
- Do not put multiple competing CTAs in the hero.
- Do not use decorative gradient text or oversized rounded elements.

### Responsive behaviour
- Desktop: two-column (text left, media right).
- Mobile: single column, text above media.

### Accessibility
- Headline is `<h1>` — only one per page.
- CTA button has a descriptive label (not just "Learn more").
- Background images use CSS, not `<img>`, so they do not need alt text.

## 2. Feature Grid

A grid presenting product features with icon, title, and description.

### When to use
- Communicating product capabilities on a landing page.
- "Why choose us" or "How it works" sections.

### Anatomy
- **Icon**: small (24 px), monochrome, functional (not decorative).
- **Feature name**: `<h3>`, 2–4 words.
- **Description**: 1–2 sentences, plain prose.

### Do
- Use 3 or 6 items for a balanced grid (avoids orphaned final row).
- Keep descriptions parallel in tone and length.
- Use simple, consistent icons.

### Don't
- Do not use more than 8 features — split into multiple sections.
- Do not use decorative icon backgrounds or colored glows.
- Do not use eyebrow labels ("OUR FEATURES") — let the section heading do the work.

### Responsive behaviour
- 1 column on mobile, 2 on tablet, 3 on desktop (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`).

### Accessibility
- Section has a visible heading (`<h2>`).
- Feature list is `<ul>` with `<li>` items.
- Icons are `aria-hidden="true"`.

## 3. Pricing / Comparison Table

Side-by-side comparison of plans or tiers.

### When to use
- SaaS pricing pages.
- Feature comparison between product tiers.

### Anatomy
- **Plan name**: column header (`<th scope="col">`).
- **Price**: prominently displayed with billing period.
- **Feature rows**: `<th scope="row">` for feature name, cells for plan availability.
- **CTA**: per-column sign-up button.
- **Highlighted column** (optional): most popular plan with subtle background.

### Do
- Use `<table>` semantics for the comparison grid.
- Include a "most popular" indicator if needed (not just color — use text too).
- Show annual and monthly pricing if both are available.

### Don't
- Do not use a CSS grid masquerading as a table — use real `<table>` for accessibility.
- Do not overload rows with too many features — 10 rows max.

### Responsive behaviour
- Below `md`: show one plan at a time with a tab or slider to switch.
- Do not horizontally scroll the full table on mobile.

### Accessibility
- `<table>` with `<caption>` ("Pricing plans").
- Proper `<th>` with `scope` attributes.
- CTA buttons per column: "Get started with Pro".

## 4. Testimonial / Quote

Social proof from customers or users.

### When to use
- Landing pages and pricing pages to build credibility.
- Near relevant features or conversion points.

### Anatomy
- **Quote text**: 1–3 sentences. Use `<blockquote>` or `<q>`.
- **Attribution**: name + role/company. Use `<cite>` for the source.
- **Avatar** (optional): small (40 px), circular.

### Do
- Use real, attributed quotes.
- Keep quotes short — 1–2 sentences are most effective.
- Show the person's name and role/company always.

### Don't
- Do not use decorative quotation marks as large SVG graphics.
- Do not add star ratings if the rating source is not verifiable.

### Accessibility
- `<blockquote>` or `<figure>` + `<figcaption>` for quote + attribution.
- Avatar images need `alt="[person's name]"` or `alt=""` if the name is shown as text.

## 5. Media Gallery

Grid or carousel of images or videos.

### When to use
- Product screenshots, portfolio items, photo collections.

### Anatomy
- **Thumbnail grid**: responsive grid of images.
- **Lightbox** (optional): full-screen viewer on click.
- **Caption**: optional text below each image.

### Do
- Use lazy loading for images below the fold (`loading="lazy"`).
- Provide meaningful `alt` text for all images.
- If using a lightbox, trap focus within it and provide an explicit close button.

### Don't
- Do not auto-advance carousels (respects `prefers-reduced-motion` and user control).
- Do not use images as the only way to convey content.

### Accessibility
- All `<img>` elements have descriptive `alt` text or `alt=""` for purely decorative images.
- Lightbox follows the same accessibility requirements as Modal (focus trap, Escape to close).
- Carousel: show Previous/Next controls; pause auto-play on focus.

## 6. Article / Long-form Content

Typography and layout for editorial content.

### When to use
- Blog posts, documentation, help articles.
- Any long-form prose content.

### Anatomy
- **Heading hierarchy**: `h1` for title, `h2` for sections, `h3` for sub-sections.
- **Body text**: 16 px, line-height 1.6–1.75, max-width 65–70 ch.
- **Code blocks**: monospace font, syntax highlighting, copy button.
- **Inline code**: `<code>` with subtle background.
- **Table of contents**: sticky side panel for long articles (> 1000 words).

### Do
- Constrain prose line length to 65–70 characters (`max-w-prose`).
- Use proper heading hierarchy (never skip levels).
- Add "Copy" button to code blocks.

### Don't
- Do not use full-width prose text on desktop — readers cannot track lines.
- Do not use `<b>` and `<i>` for semantic emphasis — use `<strong>` and `<em>`.

### Responsive behaviour
- Table of contents: sticky sidebar on desktop, collapsible accordion on mobile.
- Images: responsive (`max-width: 100%`), never overflow.

### Accessibility
- Heading hierarchy is strict (h1 → h2 → h3).
- All links in body text have descriptive text (not "click here").
- Code blocks have `role="region"` and `aria-label="Code example"`.
